# Adaptive clinical intake and demand-driven agents

## Product contract

HealthIA must not present a fixed symptom questionnaire as if it were generated by artificial intelligence.

When guarded Gemini is enabled, each clinical block is produced from:

- the patient's current message;
- answers already provided in the active interview;
- a compact authorized longitudinal context;
- the information still missing to distinguish plausible explanations and the safest next step.

The model returns exactly five questions with selectable answers and a free-text expansion field. It may clarify possible causes and level of care, but it does not confirm a diagnosis, prescribe or modify treatment.

## Token budget

A clinical block uses at most one Gemini request.

That single response contains:

1. confirmation of clinical intent;
2. the clinical focus;
3. five adaptive questions;
4. the missing information being pursued;
5. the minimum specialist roles required.

There is no separate model request for every specialist and no additional model request for JUDGE Ω. The compact prompt excludes the full chat history, full family graph and unrelated documents.

A normal two-block interview therefore uses at most two guarded Gemini requests. The final structured summary is produced without another model request unless a later evidence-backed feature explicitly justifies it.

## Demand-driven council

Interview and safety are mandatory. Other areas are selected only when relevant:

- longitudinal history for prior episodes or important chronic context;
- medication safety for medicines, allergies or treatment questions;
- documents and results when the complaint references uploaded evidence;
- family history when the patient raises hereditary context;
- privacy when consent or sharing is involved;
- follow-up when the interview is ready for a next step.

Each block activates two to four areas. The backend specialist work is deterministic and uses authorized state; it does not multiply model calls.

## JUDGE Ω gate

After Gemini returns a plan, a deterministic gate checks it without consuming tokens. It rejects a block when it:

- does not contain exactly five questions;
- repeats questions already answered;
- lacks a case-specific safety check;
- activates too many specialists;
- contains diagnostic or medication-changing directives;
- provides no evidence that the questions were adapted to the current case.

Rejected output is never shown as a dynamic AI block. HealthIA retains a safe fallback and records the rejection in structured metadata.

## Honest fallback boundary

Local zero-spend mode, an exhausted request ceiling, a provider error or a rejected plan uses the deterministic safety fallback. Metadata marks it as:

```text
question_source=safe_fallback
verdict=SAFE_FALLBACK_NOT_HACKATHON_EVIDENCE
```

The fallback keeps the product usable, but it must not be shown to judges as evidence of adaptive Gemini questioning.

A successful dynamic block is marked as:

```text
question_source=gemini_dynamic
agent_execution=on_demand
llm_status=dynamic_clinical_questions
```

and includes the JUDGE Ω score and verdict.

## Hackathon direction

This design improves the Taskmaster story because the agent does not merely chat: it decides what information is needed next, activates the minimum useful tools, validates the plan, advances the mission and preserves an auditable path to a human-safe next step.

It does not close the remaining submission gates. HealthIA still needs the visible Google ADK runtime, durable Google Cloud execution, a closed-loop mission, Cloud Run and Firestore proof, and the final demonstration package.
